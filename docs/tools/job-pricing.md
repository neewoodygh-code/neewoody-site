# Member Job Pricing tool (carpenter-pricing.html)

> Moved out of `CLAUDE.md` on 2026-11-13 to keep the always-loaded file short. Text is verbatim from CLAUDE.md; read this file when working on the area it covers, and add new detail for this area HERE, not in CLAUDE.md.

**Member pricing tool:** `/carpenter-pricing.html` — React cost-to-quote engine, now **multi-tenant on concierge-api/D1** (rewired 2026-07-16 off the dispatch worker's `/carp/*`). Every Concierge member gets their own instance: gated by the Concierge token (redirects to `/concierge/login.html` if none; page is `noindex,nofollow` as of 2026-07-18), workshop name from `/api/me`, per-member config + quotes in `pricing_configs` (migrations 0007/0008) via `GET/PUT /api/pricing/config` + `GET/PUT /api/pricing/quotes` (bulk). First open with no config → Overhead Settings screen pre-filled with GENERIC template defaults (never the owner's real numbers). **Tier multipliers and add-on percentages are member-editable** (2026-07-18) in Overhead Settings — config keys `tierMults` (basic/standard/premium/luxury) + `addOnPcts` (rush/customDesign/cnc/remoteInstall), resolved via `tierMultFor`/`addOnPctFor` (member config → template default fallback); stored in the same `pricing_configs` JSON so no migration was needed. Rationale (owner, 2026-07-18): not everyone can command the same margins, so each member sets their own rather than inheriting one fixed set. The dispatch worker was not touched; its old `/carp` data is left as-is. **Client copy (2026-07-18):** the Summary tab is the carpenter's PRIVATE view (overhead, margin %, tier multiplier, net-profit projection); a new "Open client copy →" button renders a printable customer-facing breakdown — Materials (itemised or single subtotal, member's per-view choice) + Workmanship split into **Labour · Expenses · Service charge**. Expenses = overhead+logistics encapsulated as one line (no tool-wear/capital line items — laymen balk); "Service charge" is the label for the margin (`calc.grossMargin`); tier multiplier, margin %, net projection and day-rate never appear. Materials+Labour+Expenses+Service charge reconciles exactly to `calc.quotedPrice`. Print via `window.print()`; a `@media print` block isolates `#client-copy`. **Member branding / quote letterhead (2026-07-20, member-suggested):** a carpenter's quote must carry THEIR letterhead, not Neewoody's. The client copy now renders a member-editable letterhead — **business name · tagline · phone · location · optional logo** — set in a "Your branding · quote letterhead" card at the top of Overhead Settings. Stored in the existing `pricing_configs` JSON as `config.brand {name,phone,location,tagline,useLogo,logoUrl}` — **no migration, no Worker change** (`savePricingConfig` stores config as opaque JSON). Defaults pre-fill from the member profile (`business_name`/`name`, `business_phone`/`phone`, `area`). `logoUrl` is resolved at save time so `ClientCopy` needs only `config.brand` (threaded App→QuoteEditor→SummaryTab→ClientCopy). Falls back to `session.workshopName` if no brand set. **Dedicated business logo (2026-07-20):** members can upload a real logo, separate from their headshot — a **member asset** `logo_url` (migration 0030), stored as **PNG** (transparency-preserving) in R2 at `concierge/logos/<phone>.png`, served publicly at `GET /api/media/logos/<phone>.png`; endpoints `POST/DELETE /api/me/logo` (withAuth; PNG magic-byte check, ≤300KB). Client `compressLogo` scales to fit 420px (aspect preserved) and canvas-converts to PNG (shrinks to 280px if over cap) — now in `js/concierge.js` (exported; `uploadPhoto` gained a `contentType` arg, default `image/jpeg`). Upload UI lives in **two places** (2026-07-20): the pricing tool's branding card, AND the **member profile edit modal in `directory.html`** ("Business logo" control beside the photo — rectangular `.pprev.logo` preview, Upload/Replace/Remove) so members manage it wherever they are (thumbnail + Replace/Remove + "Show my logo on quotes" toggle on the pricing side). The quote logo resolves **dedicated logo first, profile photo as fallback** (`member.logoUrl || member.photoUrl`). Reusable on storefront/directory later. Member-delete + purge-pending cascades remove the logo R2 object. **Print/PDF fix (2026-07-20):** the client copy is **portalled to `document.body`** via `ReactDOM.createPortal` so it escapes the Summary tab's `flex:1; overflowY:auto` scroll ancestors; the print CSS then does `body > *:not(.cc-overlay){display:none}` + resets `.cc-overlay` to `position:static` (was the old `visibility:hidden` trick, which left the tall-but-invisible tool occupying space → blank/clipped print pages). Rationale (owner, 2026-07-18): unlike Neewoody's one-price encapsulation, most Ghanaian carpenters below that tier must show clients what they're paying for — the split gives transparency while still hiding the private economics. **Chrome re-skinned to green/gold/cream (2026-07-18):** the shared `Hdr` is now the deep-green editorial bar (gold "Carpentry Concierge" eyebrow, cream Playfair title) used across all three screens (Dashboard/Quote editor/Overhead settings), with a **breadcrumb** below it — `Concierge › Tools › Job Pricing` (Concierge → directory.html, **Tools → directory.html#tools** = the requested back-to-tools). Header controls recoloured for contrast on green; the redundant "← Member area" link was dropped (breadcrumb covers it). **Back-out clarity (2026-07-20, member feedback "no clear way to back out"):** the breadcrumb links were muted grey (didn't read as links) → recoloured **gold + underline**; and the Dashboard `Hdr` gained a prominent bordered **"← Tools"** button (`onBack`→`/concierge/directory.html#tools`, which `directory.html` maps to the Tools tab via its hash handler) since the landing screen previously had only the subtle breadcrumb. `Hdr` gained a `backLabel` prop (defaults "← back"; in-app sub-screens keep it). **Body re-skin (2026-07-18):** all `borderRadius:0` rounded to 4px, and `FM` (was DM Mono) repointed to the Jost stack — the tool no longer reads as a "terminal/spreadsheet" and matches the editorial system (Playfair headings + Jost UI); DM Mono dropped from the font link. Numeric readouts stay right-aligned so column edges still line up. **Accommodation / out-of-town stays (2026-09-17, owner-directed):** the Logistics tab gained an **"Accommodation — out-of-town stays"** section (Nights · Rooms · Per-room/night GH₵ → `stayNights*(stayRooms||1)*stayRate`) for far jobs where the crew sleeps over (hotel/guesthouse). It adds into `logistics` in `calcQuote` (line ~266) + the Logistics-tab total, so it flows through `rawCost` → the quote and appears under **Expenses** in the client copy (encapsulated with overhead+logistics, consistent with the existing logistics treatment — no separate client line). New `q.logistics` keys `stayNights/stayRooms/stayRate` (default `''`). **Tool-guide overlap fix (2026-09-17):** on ≥1300px the floating `ToolGuide` left rail (`js/tool-guide.js`, docked at `left:16 top:--tg-top`) was covering the top-left quote-editor tab bar (Setup/Materials/…). Fixed by raising the tool's `ToolGuide.init` **`top: 112 → 150`** so the rail docks BELOW the sticky `Hdr` (~98px) + tab bar (~35px) and sits in the left gutter clear of the centred (≤700px) content. **Shared Clients registry (2026-10-05, owner-directed "same project/customer management database as the cut list generator, multiple quotes under the same client"):** quotes gained a `clientId` (alongside the existing free-text `client` display name) linking to a new cross-tool **`clients` table** (migration `0034_clients.sql` — `id, member_phone, name, phone, notes`; one row per distinct client per member) shared with `cut-sheet.html`'s Project model. Endpoints `GET/POST /api/clients` + `PUT/DELETE /api/clients/:id` in `concierge-api/src/index.js` (GET on `withAuth`, writes on `withPaid`, mirrors the `jobs`/`buy-requests` CRUD shape); `POST` is **find-or-create by name (case-insensitive)** — the mechanism that makes it safe for both tools to independently resolve "Mensah Residence" to the same row. A client is a **soft reference**: quotes/projects keep their own denormalized name so nothing breaks if a client is later deleted; member-delete + purge-pending cascades clear `clients` too. **On load, pre-existing quotes with a `client` string but no `clientId` auto-link** (find-or-create per distinct name — the "auto-group by name" migration) and self-terminate once done. The Dashboard now **groups quotes by client** (collapsible sections, newest-touched client first) instead of one flat list, and a new **Clients screen** (header button beside + New Quote) lists every client with their quote count, Rename (propagates to every linked quote's displayed name via a `clientName(q, clients)` lookup — never a per-quote rewrite) and Delete. The Setup tab's Client field was originally a text input backed by a `<datalist>` of existing clients, but see the 2026-10-05 UX-review correction below — it's now an explicit `<select>` dropdown + conditional "+ New client…" text field, for discoverability. **Important semantic split from cut-sheet's model:** cut-sheet's Project IS 1:1 a client (renaming the project renames the shared client — `linkProjectToClient` does a PUT when already linked), but the pricing tool's quotes are **many-to-one** with a client, so editing a quote's client text never renames the previously-linked client out from under other quotes — it always resolves "which client" via find-or-create (`ensureClient(name)`, no id param); only the dedicated Clients-screen Rename actually renames a shared record. Verified end-to-end locally (`wrangler dev --local`): a cut-sheet project and a pricing quote with the same typed name resolve to the identical `clients` row, no duplicate. **UX review + overhaul (2026-10-05, owner-directed — "for a new user the current UX would be very overwhelming"):** a fresh-eyes walkthrough (new test member, no saved state) found the tool dropped a brand-new member straight onto the dense Overhead Settings form with no framing, then into a Dashboard that was just "No quotes yet" — the only help was a 7-step drawer (`js/tool-guide.js`, floating mode) whose first tip ("set overhead in Settings") never said *where* Settings was. Rebuilt as a proper **Home/Dashboard landing**: the forced first-visit redirect to Settings was removed (`setScreen('dashboard')` unconditionally — Settings is no longer a gate, just reachable); a **welcome card** (shown until `hasOverhead && hasQuote`) carries a **clickable checklist** — `ChecklistRow` components for "Set your overhead" / "Add your branding" / "Create your first quote", each navigating straight to the screen that completes it (no more dead-end tips) — plus a **"+ Create your first quote"** CTA. A new **`QuickSettingsPanel`** component (day rate read-only stat, billable days, all four tier multipliers, branding snapshot, each editable inline and saved immediately via the existing `saveOverhead`) sits beside the quote list — the "regularly-tweaked settings without opening full Settings" the owner asked for, using a `.jp-home-grid` CSS class (`display:flex` stacked by default, `grid-template-columns:1fr 280px` at `≥1024px`). A short static `TipsBox` replaced the old drawer's "tips" list. **The old floating `ToolGuide` (`js/tool-guide.js` script tag + `.init()` call) was removed entirely from this page** — superseded by the above; `cutlist.html`'s own separate ToolGuide usage was left untouched (lower priority, not part of this pass). The ⚙ icon gained a text label ("⚙ Settings"). Caught and fixed one real bug in testing: `QuickSettingsPanel` originally referenced `session` without it being passed as a prop (crashed the page) — fixed by threading `session` through from `Dashboard`. **Client → Item hierarchy (same session, owner: "you can fill in Client but not particular item/furniture"):** quotes gained an **`item`** field (free text, e.g. "Kitchen cabinets", "Built-in wardrobe") — a new "Item / project" field on the Setup tab right below Client. This fixed a real gap: multiple quotes under one client were only distinguishable by ref code. Threaded through: the Dashboard's per-client quote cards now show `q.item` as the primary heading (client name already shown once at the group header — showing it again per-card was redundant); the `QuoteEditor` header shows `title={q.item||q.refId}` / `sub={clientName · refId}` when an item is set; the client-facing "Client copy" print view appends `— {item}` to "Quote for {client}"; and the `sendToInvoice` handoff now populates the Invoice Generator's `project` field from `q.item` (previously always sent empty). **Also replaced the Setup tab's Client `<datalist>` text input with an explicit `<select>` dropdown** (+ a conditional "+ New client…" text field, shown only when no existing client is selected) — a native datalist's suggestions aren't discoverable as "pick an existing one," which was itself owner-flagged feedback ("on new quote page should there not be a way to select a pre-existing client"). The Dashboard's per-client group header and the Clients screen each gained a **"+ Quote"** button (`createNew(client)` now accepts an optional `{id,name}` to pre-link the new quote) — fixes "Client page only has rename and delete options." **Tab navigation (owner: "no next button... you'd be lost"):** `QuoteEditor`'s six tabs (Setup/Materials/Logistics/Summary/Actual Costs/Notes) previously had no way through them except the top tab bar. Each tab's content now ends with a Back/Next bar (`TABS[idx±1]`), ending in a "Save quote" button on the last tab (Notes). **Dashboard project management (2026-10-09, owner: "no way to delete jobs on the landing page, make copies or rename, etc"):** each quote card gained a **⋯ actions menu** (`QuoteMenu`) — Open · Rename item… · **Duplicate** · **Move to another client…** · Mark as Draft/Sent/Accepted/Declined · **Delete quote**; the item title itself now opens the quote. **Delete has an 8-second Undo toast** (App keeps a snapshot of the quotes list taken just before the delete; any other change calls `dropUndo()` so an undo can never roll back later work). **Duplicate** deep-copies into the next ref number, appends "(copy)", resets status to Draft and clears `expenditure` (actual costs belong to the original job), and slots in right after the source. **Move** opens `MoveDialog` (existing client dropdown or "+ New client…") → `ensureClient` find-or-create, so it can never rename a shared client. The existing invoice checkboxes now also drive a **sticky bulk bar** (N selected · Mark as… · Move… · Duplicate · Delete · Clear). Added a **search box** (item / client / ref / notes), a **sort** select (Recently edited · Newest · Oldest · Highest price · Item A–Z), **counts on the status filter tabs**, a "No quotes match" empty state, an inline **Rename** link on each client group header (→ the shared `renameClient`), and an "edited <date>" stamp — `saveQuote` and every dashboard action now set **`updatedAt`** on the quote. All actions persist through the existing bulk `PUT /api/pricing/quotes` — **no backend/migration change**. Verified locally against a mocked API (duplicate, rename, status, move to a new client, single + bulk delete with undo, bulk status, search, sort, client rename; no console errors).
