# Invoice & Quote Generator

> Moved out of `CLAUDE.md` on 2026-11-13 to keep the always-loaded file short. Text is verbatim from CLAUDE.md; read this file when working on the area it covers, and add new detail for this area HERE, not in CLAUDE.md.

**Invoice & Quote Generator (`invoice-generator.html`, built 2026-09-17, owner-directed):** the owner's **client-facing invoicing system**, rebuilt from their long-running **Google Sheets invoice** (studied from `Prampram Airbnb.xlsx` — heading INVOICE/QUOTE · Date · Invoice-for · Paid-to · Invoice # · Project · a Description/Qty/Unit price/Total-price line-item table · Total/Paid/Balance · three payment options · six T&Cs · two signatory lines). Distinct from the two pricing tools — those compute *what a job costs and should quote*; this one **produces the printable invoice/quote document** clients receive. **Admin-only**, standalone single file (self-contained inline CSS/JS, **navy/gold/cream** tool chrome; the printed doc itself is clean **black-on-white A4**, Playfair/Jost/Roboto-Mono), `noindex`, **out of `sitemap.xml` and the site nav**. Loads `js/concierge.js` and gates on `/api/me` → **redirects to `/concierge/login.html?next=…` with no token, and shows an "Admins only" gate when `me.role!=='admin'`** (mirrors the `adminLink` gate). Left column = editor (Document fields: **3-way type toggle Invoice / Quote / Receipt** — **Receipt** drops the payment options and relabels every "Invoice" mention to "Receipt" (title, `<Type> for`, `<Type> #`); **auto document number** derived from the invoice date — `NWD-<quarter><MMDDYYYY>` on **calendar quarters** (`quarterOf(m)=ceil(m/3)`; Q1 Jan–Mar, Q2 Apr–Jun, Q3 Jul–Sep, Q4 Oct–Dec, so 18 Sep 2026 = Q3 → `NWD-309182026` — owner corrected 2026-09-17 from the earlier Oct-start fiscal guess to standard calendar quarters); regenerates when the date changes, `INV.numberEdited` sticks a manual override; the old `nwd-invoice-counter` sequence was replaced by this date scheme · currency default `GH₵`, date, due date, Invoice-for, Project · Line items table with live per-row + grand totals · **Discount** (`discountType` percent/amount + `discountValue`, `discountAmt()` clamped to [0,subtotal], `finalTotal()=subtotal−discount`) shown as a %/GH₵ toggle + value with a "you save" hint; the printed doc adds **Subtotal + Discount** rows above **Total** only when a discount is set · Amount paid → auto Balance (off the discounted total) · collapsible **Business header / Payment options / Terms** settings pre-filled with Neewoody's real values from the sheet, editable once and persisted). Right column = a **live preview that is exactly what prints** (`@media print` hides all chrome, resets `#doc` to full-width A4). **Local-first, NO backend / NO Worker touch** (Standing Instruction 5 safe): working state autosaves to `localStorage` (`nwd-invoice-current`), settings to `nwd-invoice-settings`, saved invoices to `nwd-invoice-list` (My-invoices library: open/Copy/Delete; auto-suggested `NWD-####` number via `nwd-invoice-counter`), plus **Back up all / Restore** as JSON (device-independent safety net, same pattern as cut-sheet). Print/Save-PDF via `window.print()`. Verified: seeded with the real Prampram data it reproduces TOTAL/Balance **GH₵ 65,092** exactly. Surfaced via an **admin-only card in `concierge/directory.html`'s Tools tab** (`#adminInvoiceCard`, `display:none`, revealed in `init()` when `me.role==='admin'` beside the `adminLink` reveal). **Account sync ✅ BUILT + DEPLOYED 2026-09-17 (owner: "yes allow sync"):** the saved-invoice library + letterhead settings + running counter now **sync to the admin's account and follow them across devices** — mirrors the cut-sheet blob pattern. Backend: **migration `0033_invoice_data.sql`** (`invoice_data(member_phone PK, data TEXT, updated_at)`, one row = the whole `{v:1,settings,list,counter}` blob), endpoints **`GET /api/invoices`** (`withAuth`) + **`PUT /api/invoices`** (`withPaid`, 1 MB cap) in `concierge-api/src/index.js`; member-delete + purge-pending cascades clear it; D1 backup enumerates tables dynamically so it's auto-included. The store is siloed per `member_phone` like every other blob (admin-only in the UI, no new auth primitive). Frontend (`invoice-generator.html`): on a live session `boot()` calls **`cloudSync()`** → pulls the blob, **`mergeInvoiceLists()`** (saved invoices by `savedId`, newer `savedAt` wins; settings by `updatedAt`; counter = max), writes the merge to local, and pushes back; `persistSettings()`/`setList()` schedule a **debounced push** (`schedulePush`, 1.5s, gated by `syncReady` so nothing pushes before the first merge). The **working draft (`INV`) stays device-local** — only *saved* invoices + settings + counter sync. A `#syncNote` shows "☁ Synced to your account · N saved"; the local **Back up / Restore** stays as the offline safety net. Concierge-only; dispatch worker untouched (Standing Instruction 5). **Push from Pricing → Invoice (2026-09-17, owner-directed):** the member Job Pricing tool's Summary tab has an **admin-only** "Send to Invoice Generator →" button (`carpenter-pricing.html`, gated on `session.role==='admin'` — `role` now added to the pricing `session` object from `/api/me`). `sendToInvoice(q,calc)` writes a same-origin `localStorage` handoff (`nwd-invoice-handoff` = `{v,ts,client,project,ref,total,desc}`) then navigates to `/invoice-generator.html`. On load `checkHandoff()` (before `cloudSync`) reads + clears the key (15-min stale guard), and on confirm seeds a **new draft** — client + one line item at the quoted total (`desc: 'Bespoke furniture (quote <ref>)'`) — which the owner then itemises/prints. One line because the pricing tool prices a job as a whole, not per deliverable. No backend change (localStorage bridge between two same-origin pages). **Opened to all paid members (2026-10-05, owner-directed UX review — "job pricing is supposed to be able to hand over to quote/invoice generator... make the admin-only invoice generator public, while keeping my own separate from everyone else's"):** the backend was already fully multi-tenant (`invoice_data` keyed by `member_phone`, same as every other blob) — only the frontend's `me.role!=='admin'` gate in `boot()` was blocking it. **The real landmine found and fixed first:** `DEF_SETTINGS` hardcoded the owner's actual business name, two real bank account numbers and T&Cs as the seeded template — opening the gate without fixing this would have shown every new member *the owner's* bank details on their first invoice. Fix: split into **`NEEWOODY_DEFAULT_SETTINGS`** (the original real template, unchanged) and **`GENERIC_BLANK_SETTINGS`** (blank business/payment/terms fields, `logoOn:false`); `boot()`, on first-ever run for an account (`!load(K_SET,null)`), seeds `NEEWOODY_DEFAULT_SETTINGS` only when `me.role==='admin'`, otherwise seeds `GENERIC_BLANK_SETTINGS` pre-filled from the member's own profile (`business_name||name`, `business_phone||phone`, `area`) — mirroring the brand-default pattern already used in `carpenter-pricing.html`'s Overhead Settings. The gap-filling backfill loop and `cloudSync()`/`restore()` merge paths were also repointed from `DEF_SETTINGS` to `GENERIC_BLANK_SETTINGS` so a schema migration can never leak the owner's values into someone else's gaps. **Logo was a second hardcoded leak:** `renderDoc()` always rendered `images/logo.png` (the owner's actual file) when "show logo" was on; now resolves a module-level `MEMBER_LOGO_URL` (set in `boot()` from `me.logo_url||me.photo_url`) first, falling back to the Neewoody asset only when a member has no logo of their own (which in practice only ever applies to the admin account). Checkbox relabelled "Show my logo on the document". **Frontend changes:** the admin-only gate became a plain logged-in-member gate (same pattern as every other Concierge tool); page chrome (title, hero copy, footer, nav pill) de-branded from "Neewoody (Admin)" to "Carpentry Concierge"; `concierge/directory.html`'s `#adminInvoiceCard` Tools-tab reveal moved out of the `me.role==='admin'` block so every approved member sees it (admin-only badge removed from its copy); `carpenter-pricing.html`'s Summary-tab "Send to Invoice Generator" card lost its `session.role==='admin'` gate so every member gets the handoff, not just the owner. **Verified locally both ways:** a fresh admin account's first run still produces the exact real Neewoody template (bank accounts, T&Cs, logo) byte-for-byte; a fresh regular member's first run produces a blank template seeded only from their own profile (name/phone/area), zero Neewoody data anywhere in the saved blob, `logoOn:false`. **Deliberately NOT merged** with Job Pricing's own "Client Copy" (the Summary tab's instant printable breakdown) — the two serve different moments (an in-flow quick total vs. a formal numbered Invoice/Quote/Receipt document) and merging the code was judged higher-risk for no real gain; they now simply hand off cleanly via the existing `nwd-invoice-handoff` localStorage bridge, which also now carries the quote's `item` name into the invoice's `project` field (see the Client→Item hierarchy note below). **Selectable quantity on handoff (2026-10-05, owner-directed):** since the pricing tool prices a job as one lump total, forwarding always produced a single `qty:1` line item — fine for a one-off piece, awkward for "10 dining chairs" priced as one job. The Summary tab's Invoice card now has a **"Number of items"** `NumInp` (default 1) with a live preview (`N × ≈unit each — total stays X`, using 2-decimal precision so the arithmetic is honest, not a rounded-whole-cedi approximation that wouldn't quite multiply out); `sendToInvoice(q,calc,qty)` adds `qty` to the handoff payload. `invoice-generator.html`'s `checkHandoff()` splits the total evenly (`unit = total/qty`, rounded to 2dp) so `qty × unit` reconstructs the original quoted total, and the import-confirm dialog shows the quantity breakdown when `qty>1`. Verified locally end-to-end: qty 4 on a GH₵9,145 quote produced a `{qty:4, unit:2286.25}` line item whose total renders as exactly GH₵9,145. **Bundle several quotes onto ONE invoice (2026-10-05, owner clarification — "selecting items so all of them are included on one invoice," not just a quantity split on one quote):** the Dashboard's quote cards each gained a checkbox (mirrors cut-sheet.html's "select cut lists, Print selected" pattern); a client group with ≥1 ticked quote shows a **"Send N to Invoice →"** button beside "+ Quote" (and a "N selected" count, plus a one-line hint once a client has 2+ quotes). `sendMultipleToInvoice(quotes, clientName, overheadCfg)` builds one line item per selected quote (`qty:1`, `unit` = that quote's own `calcQuote(...).quotedPrice`) and writes an **`items` array** in the handoff payload instead of the single `total`/`qty`/`desc` fields. `invoice-generator.html`'s `checkHandoff()` now branches: `Array.isArray(h.items)` → import all of them as separate lines on one new invoice (combined-total confirm dialog, `toast('Imported N quotes')`); otherwise falls through unchanged to the existing single-quote `total`/`qty` path from the feature above — both handoff shapes coexist, selection is scoped per client group (an invoice is for one client), and client/project pass through the same as the single-quote path. Verified locally: two saved quotes under "Mensah Residence" (GH₵3,875 + GH₵6,200), both ticked → one invoice with two line items and Balance Due GH₵10,075. **Sections + Options + total toggles (2026-10-09, owner: "sometimes a client asks for three different options of an item — wall panelling in laminate, plywood or drywall … a way to group them and toggle totals on or off for everything or per section"; owner chose the recommended design over raw on/off toggles, which can produce nonsense totals):** line items can now be grouped into **sections** (`INV.sections[] = {id,title,kind:'items'|'options',showSub,options:[{id,name}],chosen}`; a line carries `sec` and, inside an options section, `opt`). Lines with no valid `sec` are the **loose lines** at the top, so every invoice saved before this renders and totals exactly as before (`ensureModel()` backfills `sections:[]`/`showTotal:true`). **Items section** = always counts, per-section **"Show subtotal"** toggle (prints a "Subtotal · <title>" row). **Options section** ("client picks one", e.g. Option A Laminate / B Plywood / C Drywall; each option can hold several lines, and a one-line option with no description prints as just its header row) has a **Chosen** radio per option + "No choice yet": with no choice the grand total becomes a **min–max range** (`subRange()`/`finalRange()`, "TOTAL (BY OPTION) GH₵ X – Y" + "Depending on the options chosen"); once chosen it counts like normal lines — on a **Quote** the other options print struck through with a "Chosen" badge, on an **Invoice/Receipt** only the chosen option prints. Discount applies to both ends of a range. Document-wide **"Show the grand total on the document"** (`INV.showTotal`) hides the total box + totals block for comparison-only quotes. **Guard rail:** an Invoice/Receipt with an unchosen options section shows a red warning in the editor and **`doPrint()` refuses to print** until a choice is made (options only make sense on a Quote). Switching an options section back to Items keeps only the chosen (or first) option's lines, after a confirm. Saved-library entries now store `totalMax` so ranged quotes show the range. **Job Pricing → "Send as options →"** (`carpenter-pricing.html`, shown beside "Send N to Invoice →" when ≥2 quotes in a client group are ticked): `sendMultipleToInvoice(..., asOptions=true)` sets `asOptions` on the `nwd-invoice-handoff` payload, and `checkHandoff()` builds a **Quote** with one options section (one option per quote, named by its item, priced at its quoted total). Local-first/no backend change (sections ride inside the existing saved-invoice blob). Verified locally against a stubbed account: loose line + Kitchen items section + 3-option panelling section → range GH₵11,600–14,700; 10% discount on both ends; choosing Plywood → GH₵11,970 (quote strikes the others, invoice shows only Plywood); show-total off hides both total blocks; invoice print blocked until chosen; legacy invoice unchanged; reload persists sections; pricing handoff → 3-option quote. **Document style panel + tagline fix (2026-10-11, member feedback via owner — a JWC&C member's client said their business name "looks like a cartoon" in Playfair Display, and the line under it read Neewoody's hardcoded "Bespoke Furniture & Carpentry · Accra"):** (1) **Tagline leak fixed:** `renderDoc()` hardcoded Neewoody's tagline for EVERY member; it's now `SETTINGS.tagline` (editable "Tagline" field in Business header; blank = no line). `normalizeSettings()` (now used by initial load, `cloudSync`, `restore` and first-run seeding instead of raw `Object.assign`) backfills a missing `tagline` with Neewoody's line ONLY when `bizName` matches /neewoody/i (so the owner's letterhead is unchanged), blank for everyone else. (2) **"Document style" card** (`#setStyle`, settings — so it syncs across devices with the letterhead): **font preset** `font` = classic (Playfair+Jost, the old look) · modern (Montserrat+Jost) · traditional (Libre Baskerville+Lora) · clean (Jost) — each option button previews the member's own business name in that font; **accent colour** `accent` (6 swatches + custom picker, validated `#rrggbb`) drives the table header, total-box border, option rows and payment-option headings; **header layout** `headerLayout` left|center (centred stacks logo/name/tagline and runs contact details inline with " · "); **logo size** `logoSize` s/m/l = 40/52/72px; **show toggles** `showName` (hide the name text when the logo spells it), `showPaidTo`, `showProject`, `showSign` (signature lines); **paper** `paper` a4|letter (injects a `#pageStyle` `@page` rule + `#doc.letter` width). Implemented as CSS vars on `#doc` (`--d-head/--d-body/--d-accent/--d-logo`) set in `renderDoc()`; fonts added to the Google Fonts link. (3) **Phone preview fixed:** the member's screenshot showed the page cropped on the left — `#doc` is now always laid out at true paper width and `fitPreview()` scales it down (`transform:scale`) to the column, sizing `.doc-scroll`'s height to match (re-run on render, resize, and logo load); `#previewCol/#inputCol{min-width:0}` stop the grid column growing to the doc's width.
