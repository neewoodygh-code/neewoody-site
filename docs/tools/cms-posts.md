# CMS posts (admin-uploaded projects)

> Moved out of `CLAUDE.md` on 2026-11-13 to keep the always-loaded file short. Text is verbatim from CLAUDE.md; read this file when working on the area it covers, and add new detail for this area HERE, not in CLAUDE.md.

**CMS posts (admin-uploaded project modals):** `admin.html` (React, X-NWD-Key auth) lets the owner create posts — title, location, category, **multi-page targeting**, write-up, up to 4 images (uploaded via Worker `/api/posts/upload`). `js/cms-posts.js` runs on any page with `<section id="cms-posts" data-page="<slug>">`, fetches `/api/posts?page=<slug>`, and renders cream cards that open a modal (unified with the `pm-*` two-column style — big main image + thumbnail strip + write-up + click-to-zoom; keeps its own `.cms-*` classes to avoid clashing with inline `pm-*`). Targetable pages are the `PAGES` array in `admin.html`; section labels are `PAGE_LABELS` in `cms-posts.js`. The Worker filters generically by membership in the post's `pages[]`, so **adding a new target page needs no Worker change** — add it to `PAGES` (admin), `PAGE_LABELS` (cms-posts.js), and drop a `#cms-posts[data-page=…]` section on the page. Home is wired (slug `index`, "Recent Work"); the homepage's old hardcoded cards were renamed "Featured Projects". Post fields map: category→eyebrow, title→h2, location+year→meta, write-up paragraphs→body. **Native cards + homepage removed (2026-11-11, owner-directed):** the CMS no longer targets the homepage — the `#cms-posts` section and the `cms-posts.js` include were removed from `index.html` and `index` was dropped from admin.html's `PAGES` (the one existing post that also targets `index` is harmless; it still shows on Solid wood). **Posts now render as each page's OWN project cards by default:** a page supplies `<template id="cms-card-tpl" data-into="<grid selector>">` holding one card in that page's markup with `data-cms-img|title|category|location|year|caption|type` slots (`type` = "category · location"); `cms-posts.js` (`nativeCard()`) fills them, drops empty slots, prepends the cards to that grid newest-first (`.cms-native`), and clicking opens the CMS gallery modal. Templates exist on wardrobes (`.wd-cards-grid`, `.wd-card`; no `data-cat` so it shows under "All"), kitchens (`.kt-grid` — the newest post takes the big first-child tile), beds (`.bd-grid`), dining-living (`.dl-grid`, same first-tile rule), solid-wood (`.sw-species-grid`) and portfolio (`#pf-made-grid`, the "Made to order" grid). **tv-units + shelving have no project-card grid, so they keep the standalone `#cms-posts` section** (fallback path, unchanged). To add a new page: drop a `#cms-posts[data-page]` section + a `cms-card-tpl` template, add the slug to admin `PAGES` + `PAGE_LABELS`. Script loaded as `cms-posts.js?v=20261111b` — bump on change.


## 2026-11-14: posts are built into the pages (owner go-ahead, design plan Step 5)
- `src/cms.js` reads `GET /api/posts?page=<slug>` from the dispatch Worker **at build time** (read only; the Worker, its KV and R2 were not changed) and turns each post into a normal gallery card: WebP at 500/800 px for the card and 1600 px for the viewer, quality 68. The two existing posts went from 3 to 8 MB per photo to 4 to 450 KB.
- Cards carry `data-cms-id`. `js/cms-posts.js` (now `?v=20261114`) skips any post already on the page, so a post made after the last build still appears straight away through the old browser loader and becomes a built-in card at the next site build (any push to `main`).
- Pages with a gallery get the cards at the front of that gallery; pages without one (TV units, shelving) get a "Recently finished" gallery when they have posts.
- If the posts list or a photo cannot be fetched during a build, that post is left out and loads in the browser as before. A build never fails because of this.
- Gotcha: with a remote image, `getImage({ inferSize: true, width })` kept the ORIGINAL height (1600 x 8160 output). `cms.js` calls `inferRemoteSize()` itself and passes width and height.
- `admin.html`: `shrinkImage()` resizes a photo in the browser before upload (longest side 2000 px, JPEG 0.82; tested 6.6 MB to 320 KB). Falls back to the original file on any error.
- Not done (would need a Worker change or a secret in a public page): rebuilding the site automatically when a post is saved.
