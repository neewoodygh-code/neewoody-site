**Cutlist generator:** `/cutlist.html` — parametric wardrobe cutlist for carpenters. **Print/PDF fix (2026-07-20):** the results page `#rpage` is `position:fixed; overflow-y:auto`; the old `@media print` rule targeted `.rpage` (a class that never matched the `id="rpage"` element) and never reset the fixed/overflow, so printing clipped the list to one screen (blank/partial PDF). (c) Print buttons relabelled `⎙ Print`→`⎙ Print / Save PDF` (the native print dialog is the Save-as-PDF path; no separate PDF button exists — `window.print()` IS it). **Member-bar back-nav (2026-07-20):** the logged-in `#member-bar` had only a subtle "Directory →" link and no way back to the Tools tab → added a prominent bordered **"← Tools"** link (`concierge/directory.html#tools`) beside a "Directory" link. The hero logo (now `logo.png`) is black-on-dark-green → given `filter:invert(1) brightness(1.4)` so it reads as a crisp white mark (same asset-is-a-dark-logo issue as the footer). **Edge Band Sheet — print + Ghana machine-shop convention (2026-07-20, member feedback):** the edge indicators were background-coloured `<div>` bars, which browsers **strip from printouts by default** (backgrounds don't print) — so a saved/printed cut list showed NO edgeband marks. Rebuilt each part as an **inline SVG** (vector `<line>` strokes always print, no `print-color-adjust` reliance) drawn in the local convention: **1 tick straddling an edge = edgeband that edge · 3 ticks = double the board (glue 2 up) then edgeband**. Data model: `ebState[k]` kept per-edge band booleans `{t,r,b,l}` + added a per-part **`dbl`** flag (whole board doubled → all its banded edges render 3 ticks). Helpers `ebLine`/`ebTicks`/`ebHit` in `buildEbSheet`. A legend spells out 1-tick vs 3-ticks. Also added `#rpage *{print-color-adjust:exact}` belt-and-braces. **Revised per owner feedback (2026-07-20, machine-operator clarity):** (1) the per-edge model is now a **tri-state** (`0` none · `1` band=1 tick · `2` double+band=3 ticks) — the old per-part `dbl` flag + visible **"×2 double" button were removed** (a "DOUBLE" label under each box confuses operators). **Doubling is now click-twice:** tapping an edge cycles none→band→double→none. (2) Dimensions are drawn in the **machine-shop layout — length rotated on the RIGHT of the box, width on the BOTTOM** — replacing the "W × D mm" line (that format isn't how shops write it). **(3) Grain direction (2026-07-20):** "length" = the **grain-direction** dimension, which is *usually* the longer side but the client can reverse it (drawers especially). Default length = longer dim; **tapping the middle of a box** toggles a per-part **`gflip`** flag that swaps which dimension is the length (right) vs width (bottom). Faint vertical grain lines are drawn in each box (grain runs along the length) + a legend item, and a transparent `.eb-grain` centre hit-rect handles the tap (`rerenderEbSheet`). `initEbState` normalises legacy booleans → `0/1`, drops any old `dbl`, and defaults `gflip=false`, so saved cut lists still load. **Per-section page breaks on print (2026-07-20, owner request):** each major result section starts on a fresh page so none begins part-way down a sheet. Sections that should break carry a **`.pgbreak`** class; **Parts List has no `.pgbreak`** so it shares page 1 with the alpha disclaimer (avoids wasting a page on the note alone). `@media print{.pgbreak{break-before:page;page-break-before:always}}` + `break-after:avoid` on section headers so a header never orphans at a page bottom. **Final grouping (owner, 2026-07-20):** page 1 Parts List · page 2 Cut List · page 3 **Zone Summary + Material Summary + Construction Notes together** (only Zone Summary carries `.pgbreak` to start the group; Material Summary + Construction Notes flow under it) · page 4 Edge Band Sheet.

**Fixes 2026-11-17 (owner: "fix the other stuff"; found while planning the Smart Generator, `docs/tools/smart-cutlist-plan.md`):**
- **Door widths (bug):** every hinged door got the full outer overlay (board − clearance) on both sides, even over a shared divider, so neighbouring doors overlapped; the default 3-section wardrobe's doors totalled 2424 mm on a 2400 mm carcass. `calculate()` now works out each section's front span with `frontSpan(si)`: outer edges (carcass side, or unit end on a butt join) cover board − edge clearance; a shared divider (or shared-divider unit join) with a front on both sides is split, each front covering (board − door gap) / 2; a divider next to a section with no door or drawers is covered like an outer edge. Several doors on one section share the span less the gaps between them. Door and drawer-front widths round DOWN (never wider than the span). Default wardrobe now: 800 + 792 + 2×399 + gaps + edges = 2400 exactly.
- **Doors use the right setting:** the door calc used the *shelf* clearance (`i-clear`) as the edge clearance; it now uses the Doors-tab "Edge Clearance" (`i-overlay`, default 2, and the code fallback was 11, now 2). Both default to 2, so default output for the outer edges is unchanged. The Doors callout ("Standard is 11mm") was rewritten.
- **Drawer fronts** are now the same width as a single door on that section (was opening + 2 × edge clearance − door gap, a different formula).
- **Groove depth (owner: "differs person to person, router or table saw blade, make it dynamic"):** new Doors-tab field `i-groove` (`S.groove`, default 8 mm), remembered on the device (`localStorage nwd-cutlist-groove`) and saved with the cutlist. Inset back = opening + 2 × (groove depth − 1 mm play). Before, it assumed a groove as deep as the back is thick (opening + 2 × 3 mm). The info panel and construction note give the groove width, depth and the 1 mm play.
- Verified in Chromium: default, groove 10, 2 units butt, 2 units shared, a section without a door; no page errors. What's new #40.
- **Shared-divider unit join REMOVED (owner 2026-11-17: "a shared panel is just one carcass divided, remove the option"):** the Unit Join select is gone (a hint explains why); `S.modJoin` is always `'butt'`, old saved configs with `'shared'` load as butt (4 side panels for 2 units); unit joins always get the outer-edge door overlay. This replaces open item (a) below.
- **Drawers behind doors = a separate drawer chest (owner method, from the Bortianor glass-front wardrobe, 2026-11-17):** "a separate box; strips screwed to the outside front on either side to fill in the gaps, then front strips glued to that which partially overlap onto the chest sides, so the fronts take the rest of the sides minus the clearance gap. Box is set back 8 cm." Applies to any drawers zone in a section whose door is on. New Doors-tab fields (saved with the cutlist): Chest Set Back `i-chset` 80, Gap Each Side `i-chgap` 18 (= filler thickness), Filler Strip Width `i-chstrip` 60 (owner's "6 cm blocks"), Face Strip Overlap `i-chover` 9. **3D view (built 2026-11-18, owner: "we can do better with the image output instead of the 1-dimensional one we have now"):**
- `js/cutlist-3d.js` (`window.Cutlist3D`): `buildModel(S, r)` places every part of `calculate().parts` in 3D. **Sizes come only from the cut list; the file decides positions only.** It consumes each part by name (`take`) and checks every part is used exactly `qty` times (`Cutlist3D.check(S, r)` returns `{warnings, clashes, boxes}`; mismatches are also logged to the console). `clashes()` lists parts that run into each other by more than 0.5 mm (inset back and subframe left out: the back sits in its groove, the subframe is only roughly placed). `calculate()` now also returns `geo` (unit/section widths, panel depth, groove, mid-rail count, each section's front overlays) for positions.
- Model axes: x left to right, y floor up, z carcass front (0) to back. Zones stack from the top, scaled to the inner height like the flat front view; a drawer chest or drawer stack sits at the bottom of its zone. Hanging rails are drawn as grey hardware (not on the cut list).
- Diagram card has a **3D** tab (`S.diagView='3d'`, `#w3d`; X-Ray hidden there): drag to turn, pinch/scroll to zoom, **Pull apart** slider (doors and fronts come forward), **Doors** see-through / show / hide, tap a part for name, size and qty. Rebuilt 120 ms after each change.
- Results page and printout start with a **3D View** card (`#r3d`): a 1400 × 1000 still (front left, from above, doors see-through), prints on page 1 above the parts list. If 3D can't load, the card is removed.
- three.js r160 is **self-hosted** in `js/vendor/three/` (`three.module.min.js` 670 KB, about 170 KB compressed; `OrbitControls.js` with its import rewritten to `./three.module.min.js`; MIT `LICENSE`), loaded with `import()` only when the 3D tab or a result opens. Does not work from `file://` (browsers block module imports there; a message says so).
- **Bug the model exposed, fixed:** drawer box fronts/backs were cut the same width as the base with the sides outside them, so every box was 2 × board wider than the runner space (default: 786 mm box in a 776 mm opening). Now base = box outside width (opening − 26, or chest inside − 26), front/back = that − 2 × board, between the sides. Applies to outside drawers and the drawer chest.
- **Default layout changed:** section 3 now lists shelves above the drawers (was drawers on top), so the default drawer chest sits on the carcass bottom as the owner builds it. A construction-note check warns when a drawer chest is not the bottom zone (needs a fixed shelf under it).
- Verified in Chromium (SwiftShader): default, drawers without a door, 2 units × 4 sections: all parts placed (63 / 53 / 77), list and model match, no clashes; viewer, pull-apart and results picture screenshotted; print to PDF puts the picture on page 1. What's new #42.
